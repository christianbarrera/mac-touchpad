# Developing Mac Touchpad

How the code fits together, the protocol, the security model and the traps found along the way. For setup and everyday use, see the [README](../README.md).

## Quick start

```bash
python3 -m venv .venv && .venv/bin/pip install --require-hashes -r requirements.txt   # pyobjc is skipped off-macOS
.venv/bin/python tests/smoke_test.py      # end-to-end over TLS, key store, embedded server; must stay green
./touchpad dry-run                        # logs input instead of injecting it; no Accessibility needed
```

`./touchpad` creates `.venv` on first use. The smoke test starts servers in `--dry-run` mode with a throwaway `HOME` and random ports, so it never touches your real configuration. It runs on Linux too, but injecting input, the macOS dialogs, launchd and the app bundle need a real Mac.

`--dry-run` shares the real configuration folder, so pairing in dry-run still shows the Mac's dialog. Only tests skip it, by setting `TOUCHPAD_TEST_AUTO_APPROVE=1` together with a throwaway `HOME`. The configurations in `.claude/launch.json` do the same.

## Repo map

```

server/touchpad_server.py  aiohttp HTTP+WS server, auth/pairing flow, Server class (watcher loop), CLI flags
server/keystore.py         CA key stores (KeychainKeyStore / FileKeyStore) + verified migration
server/tls.py              local CA (key read lazily from a key store), leaf cert, .mobileconfig
server/input_mac.py        CGEvent mouse/scroll/gestures/keys/media keys + Accessibility check (macOS only)
server/dryrun.py           DryRunInput: logs instead of injecting (cross-platform)
server/devices.py          paired-device store + signature/HMAC verify (re-reads the file each time)
server/networks.py         network fingerprint (DHCP-based) + trusted-network store
web/index.html|style.css   phone UI (dark, safe-area aware)
web/app.js                 gestures, rAF batching, connection/auth state machine, remote, keyboard, settings
web/hmac.js                pure-JS SHA-256/HMAC fallback (Safari hides crypto.subtle outside secure contexts)

web/manifest.webmanifest   PWA manifest; icons generated by tools/make_icons.py (stdlib only)
tools/build_app.sh         builds/signs/self-tests/installs the app; tools/launcher.c is its main executable
tools/setup_signing.sh     one-time signing identity in ~/Library/Keychains/mac-touchpad-signing.keychain-db
tests/smoke_test.py        end-to-end test, dry-run, throwaway HOME, random port
requirements.in → .txt     top-level pins → full pins + sha256 hashes (uv); pyobjc marked darwin-only
docs/screenshots/          phone-size screenshots of each screen
```

**Runtime state** lives in `~/Library/Application Support/mac-touchpad/`:
- `token`: the URL path code
- `devices.json`: paired phones' public keys (mode 600)
- `networks.json`: trusted networks
- `settings.json`: app settings, e.g. `allow_when_locked`
- `app.lock`: single-instance lock
- `pairing-open-until` and `setup-open-until`: the pairing and setup windows
- `tls/`: `ca.crt`, `server.crt`, `server.key`

In the app, the CA private key is the login-keychain item "Mac Touchpad: certificate authority key" (service `local.mac-touchpad`, account `ca.key`). Source runs keep it as a mode-600 `tls/ca.key` instead. The app logs to `~/Library/Logs/Mac Touchpad/`; source runs log to `logs/` in the repo (gitignored).

## Architecture and protocol

- **HTTPS** (`--tls-port`, default 8766): `GET /<token>/` serves `web/`, and the WebSocket is at `/<token>/ws`. Any other path returns 404.
- **Plain HTTP** (`--port`, default 8765): serves only the token-gated setup page, the `.mobileconfig` profile and the `.crt`, never the app. It is open only until the first phone is paired and for 15 minutes after `./touchpad pair`.
- **WebSocket messages:** each message is a JSON object or an array of them.
  - Server → `{"t":"hello","host","nonce","v":3,"natural"}`. `natural` is the Mac's natural-scrolling setting.
  - Phone → `{"t":"auth","id","sig"}` → `auth_ok {name, pk}`, or `auth_fail` and close.
    - `sig` is hex `r||s`, an ECDSA P-256 / SHA-256 signature over `"mac-touchpad auth v1:" + nonce`.
    - Legacy shared-key phones send `mac` = HMAC-SHA256(key, nonce) instead, then upgrade with `rekey {pub}` → `rekeyed`.
  - Phone → `{"t":"pair","name","pub"}` → `pair_wait {code}` → the Mac dialog → `paired {id, name, pk}`, or `pair_denied {reason, retry_in?}` and close. `reason` is one of `refused`, `badcode`, `cooldown`, `busy`, `locked`, `closed` or `badkey`. `pub` is a hex uncompressed P-256 point.
  - Unauthenticated sockets are closed after 20 s, not counting time spent in the pairing dialog.
  - **After auth:**

    | Message | Meaning |
    |---|---|
    | `m {x,y}` | move, in Mac points; the phone has already applied the gain |
    | `s {x,y,ph,mo}` | scroll pixels, with optional gesture and momentum phases |
    | `z {ph,v}` | pinch |
    | `rot {ph,v}` | rotate |
    | `c {b:l\|r}` | click |
    | `d {b}` / `u` | button down / up |
    | `k {k, m:[mods]}` | key |
    | `txt {s}` | text, at most 500 characters per message |
    | `media {k}` | media key |
    | `p {i}` | ping, echoed back |

    The server may send `locked` (input ignored while the screen is locked), and `idle` or `auth_fail` mid-session (idle timeout, or the phone was forgotten).
- **Pairing policy:**
  - The first phone may pair while none are paired. After that, only within 120 s of `./touchpad pair`, for one phone, then pairing closes again.
  - `--no-pairing` turns pairing off entirely. One dialog runs at a time.
  - The phone shows a 4-digit code that has to be typed into the Mac's dialog.
  - "Don't Allow" puts that IP on a 5-minute cooldown.
- **Network policy:**
  - A watcher runs every 5 s. The server listens only while the current network's fingerprint is trusted, and binds only to that interface's address.
  - The fingerprint is a SHA-256 of router IP | DHCP server | netmask | DHCP domain, read from `route -n get default` and `ipconfig getpacket`.
  - `--any-network` bypasses this; the tests use it.
- **TLS:**
  - A local CA (P-256), name-constrained to `.local`, `localhost`, RFC 1918, loopback, link-local and 100.64/10.
  - The leaf certificate covers `<LocalHostName>.local` plus the permitted LAN IPv4 addresses and is valid for 397 days. It is re-issued and hot-swapped into the SSLContext whenever that address set changes.
  - Deliberately no HSTS: it would break the plain-HTTP setup port on the same host name.
- **Gain curve (phone side):** `gain = sens × (1 + accel × 1.9 × clamp(speed_px_per_ms − 0.1, 0, 3))`, with defaults sens 1.3 and accel 1.0. The tunables are at the top of `web/app.js`.

## The app bundle

- **Menu bar:** plain PyObjC (`NSStatusItem`, `server/menubar.py`), not `rumps`. That avoids an extra dependency (rumps is unmaintained). Turn On/Off isn't persisted: the app always starts on, so a lid-closed Mac is never stuck off.
- **Server embedding:** `touchpad_server` exposes `build_parser()`, `run_one_shot()` and a `Server` class. Its `serve()` coroutine runs on the main thread (CLI) or a background thread (app), with thread-safe `stop()`, `set_enabled()`, `set_allow_when_locked()`, `poke()` and `status()`.
- **Bundle:** no py2app.
  - `tools/build_app.sh` copies into the bundle: Homebrew's Python 3.13 (libpython plus a trimmed stdlib), OpenSSL, the hash-pinned `.venv` packages, and `server/` + `web/`.
  - `tools/launcher.c` is the main executable. It embeds Python with `PyConfig_InitIsolatedConfig`: no `PYTHON*` environment, no user site, no cwd, no `site.py`, and an explicit `sys.path`.
  - Homebrew install names are rewritten to `@executable_path/../Frameworks`, and Homebrew's `LC_RPATH`s are deleted.
  - `--selftest` fails the build if any library loads from outside the bundle, `/System` or `/usr/lib`.
- **Signing:**
  - A self-signed RSA-3072 certificate made by `tools/setup_signing.sh`. Its key is non-extractable and lives in its own keychain, which has its own password, is off the search list, and locks after 5 minutes or on sleep.
  - The build unlocks that keychain once and locks it again right after.
  - Hardened runtime with `disable-library-validation`, which is needed without a Team ID.
  - The designated requirement pins the bundle id and the leaf certificate.
- **Accessibility (TCC):** the grant is tied to the designated requirement, so it survives rebuilds.
- **Keychain:**
  - The CA key is a generic-password item in the file-based login keychain.
  - Its partition list holds build cdhashes, since there's no Team ID, so **each new build needs one "Always Allow"**. `build_app.sh` runs `--check` right after installing to surface that dialog.
  - The key is read lazily, only when a leaf has to be (re)issued.
- **Login item:** `./touchpad install-agent` writes a launchd agent (`local.mac-touchpad`) pointing at the app's executable, with `KeepAlive` on crash, `LimitLoadToSessionType Aqua` and `AssociatedBundleIdentifiers`.
- **Install:** `sudo` installs a root-owned `/Applications/Mac Touchpad.app`. The script then deletes its signed `build/` copy, which would carry the same grant while being user-writable.

## Security model and known risks

The README's "How the app is protected" covers what's defended. Known open risks, most important first:

1. **The TOFU setup step.** The plain-HTTP setup page could be swapped by someone on the same Wi-Fi to serve their own profile. The CA fingerprint is printed on the Mac and shown on the page for comparison.
2. **Local malware running as the user** could edit `devices.json` to add its own public key, then drive input through the server. Moving the device list into the keychain, or signing it, would help. `tls/server.key` is also still a file.
3. **The signing identity is the crown jewel.** Whoever can sign with it gets an app macOS treats as Mac Touchpad. A keylogged signing-keychain password or login password defeats the protection.
4. **The network fingerprint isn't unique.** Two networks using the same router defaults look alike. It keeps the server quiet in most other places, but it isn't a security boundary.

## Gotchas learned

- **Chromium throttles rAF to about 2 fps when a browser pane is hidden.** Test batching with the 24 ms fallback flush in mind; don't "fix" it by removing rAF.
- **macOS hides the Wi-Fi SSID/BSSID and the ARP table** from processes without extra permissions. That's why the network fingerprint is DHCP-based.
- **iOS gives Home Screen web apps storage separate from Safari.** The pairing key must be created inside the installed app; the UI steers users there.
- **TCC attributes Accessibility to the *responsible* process.** Started from Terminal, the grant belongs to Terminal.
- **AppleScript dialog and notification text is passed as `argv`,** never interpolated. Keep it that way (injection safety).
- **`touchpad` runs under macOS's `/bin/bash` 3.2:** no `set -u` (an empty `"$@"` counts as unbound), no associative arrays.
- **Regenerate pins with** `uv pip compile requirements.in --universal --generate-hashes --python-version 3.11 -o requirements.txt`.
- **codesign "Allow" covers one signature, not one run.** A bundle with ~100 libraries meant ~100 password dialogs. Hence the separate signing keychain that codesign may use silently while it's unlocked.
- **Keychain items made by an app without a Team ID are partitioned by cdhash.** Rebuilds can't read them until approved once. TCC, by contrast, matches the designated requirement.
- **Any signed copy of the app carries its permissions.** Don't leave signed builds in user-writable places; editing their Python files doesn't change the cdhash.
- **`--check` must be started with `open -W -n …`**: run from a terminal, TCC answers for the terminal, not the app.
- **The firewall prompt appears on the first incoming connection,** not when the app starts listening.
- **Homebrew links everything with `LC_RPATH /opt/homebrew/lib`,** a user-writable folder: strip it when bundling.
- **PyObjC treats every method of an NSObject subclass as a selector;** helpers need `@objc.python_method`.
- **If the iPhone installs and trusts the profile but Safari still warns,** suspect the CA's name constraints first. Removing them in `server/tls.py` and then running `./touchpad reset-certs` is the fallback.
